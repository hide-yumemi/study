PDOのデータベース接続
接続失敗時にPDOExceptionという例外に
エラーメッセージが入っている
PDOExceptionが生成された時にそれを受け取って
処理を行う為に、try-catchで行う
try{
  データベース接続命令
}
catch(PDOException 変数){ //PDOExceptionの受取エラーメッセージは変数→getMessage()で取り出し
  接続失敗時に処理
}

array(PDO::ATTR_EMULATE_PREPARES => false));
これはプリペアドステートメントでのbindの実行タイミングを指定している。
true php側でbindしてSQL文を完成させてデータベースへ渡す
false bind前のSQL文とbindする値を個別にデータベースに渡し
      データベース側で、SQL文を完成させる。
現在はセキュリティ上false(データベースに個別渡し)で
やるべきであるという考えになっている。(IPAも公式に表明している)

プリペアドステートメントを使用しSQL文を実行
ユーザーの入力値に関して悪意目的で
SQL文では「:~」という仮の名前を付け
後からbindしてSQL文を完成させる
プリペアドステートメント用変数＝接続を代入した変数->prepare(SQL
文)
とし、ここでは「:~」の形にしておき
プリペアドステートメント用変数 -> bindParam(':~';値の代入された変数)
プリペアドステートメント用変数 -> bindValie(':~','値')
を使用してbind指定を行う。

プリペアドステートメントは1つのプログラム中に
何回でも実行できるが、同時に複数が存在する事は出来ない
その為、プリペアドステートメントは1つ開始したら
終了をプログラムで宣言してから次のという流れで行う。
プリペアドステートメントの終了はプリペアドステートメント用の
変数にnullを代入する。
今回は$stmtを使用しているので、$stmt=null;
で終了となる。

システム全体の処理速度向上とセキュリティ対応の為
データベースは使い終わったらすぐ切断する
PDO接続の切断は接続命令を代入した変数にnullを代入する
今回接続を代入したのは$pdoなので
$pdo=null;
で切断。

ログイン時の処理

SELECT文を
 取得カラム パスワード
 WHEREの条件 ログインに使用するユニークカラム（今回はname）
 で実行し
 取得あり パスワード一致確認
 取得0    ユーザーが存在しない
 となる。

 ログイン時の処理
 SELECT文で取得後にfetch命令を実行すると
 取得なし fetchを代入する変数にfalseが入る
 取得在り fetchを代入する変数に、カラム名をキーとした
            連想配列で取得したカラムの値が入る。
今回、fetchを$resultに代入しているので
if($result):とすると
true 取得在り
false 取得なし
となる。

登録内容の変更
本人確認
他人が勝手に変更できないようなログイン中であっても
パスワード等で本人確認を行う
今回は確認成功したら、UPDATE文で変更処理
UPDATE文は条件を満たす行全てを変更するので
WHEREでの絞り込みを忘れないように。

変更と同様に、削除処理に関しても本人確認を行う
（ECサイトの商品削除でも削除しようとしている人の確認を行う）

本人確認完了したらDELETE文で削除
UPDATE文同様条件を満たした行を全て削除する
WHEREがなければ、テーブルの全データ削除となるので
WHEREの条件による絞り込みをしっかり行う。
