-------------ホワイトボード-----------------

• dbname：接続するデータベース名
• host：接続するホスト名
（サーバーの場所。例：localhost など。http:// は含まない）

• port：指定したデータベースに接続する時に使用するポート番号
省略時は、MySQLデータベースデフォルトのポート番号を使用する
（デフォルト番号：3306）

【補足】
ポート番号をプログラムに直接書いてしまうと、
それ以外のポート番号を採用しているデータベース環境で
動かなくなる場合がある。

• XAMPPのデフォルトポート番号は（3306）となっており、省略することで自動取得して接続される。

• MAMPのデフォルトポート番号は（8889）などになっている。
そのため、今回用意してある bbs2.php ではポート指定を省略している。

【hostの指定について】
レンタルサーバーでは、管理画面などでホスト名が指定される。
通常は、WebサイトのURLが https://sample.co.jp であれば、https:// を除いた sample.co.jp（またはサーバー固有のホスト名）を指定する。


PDO接続時に文字コードを指定し、接続を静的接続にする

• 静的接続（静的プレースホルダ）
プリペアドステートメントでの値のバインド（bind）をデータベースサーバー側で行う手法。
SQL文の型（テンプレート）と、バインドする値を別々のタイミングでデータベースサーバーに送信する。

• 動的接続（動的プレースホルダ / エミュレーション）
プリペアドステートメントでの値のバインドをPHP（プログラム）側で行う手法。プログラム側でSQL文を完成させてからデータベースサーバーに送信する。


現在、IPA（情報処理推進機構）は「静的接続」がよりセキュリティ対策として有効であるとしている。
一部のプログラミング言語において、動的接続で Shift_JIS を使用した際にセキュリティホール（SQLインジェクションの脆弱性）が見つかった歴史背景もあり、現在のPHP公式の推奨は以下の2点となっている。

1. DSN（接続文字列）で文字コードを明確に指定すること
2. 静的接続にすること（エミュレーションをオフにする）

静的接続にするために、接続時にオプションを指定する。
今回は charset=utf8 と指定しているが、この文字コードはデータベースの文字コードに合わせる必要があるため、データベース作成時に utf8mb4 とした時は、PHP側でも charset=utf8mb4 とする。


【静的接続を指定する書き方】
PDO接続時に、以下のように指定する。
接続を代入する変数 = new PDO(サーバー情報, 接続するユーザーID, ユーザーのパスワード, オプション配列);

静的接続の指定（エミュレーションの無効化）は、
オブジェクト生成時の第4引数に
array(PDO::ATTR_EMULATE_PREPARES => false) を渡すことで行う。

php
// PDO接続の記述例
$dbname = 'mysql:host=localhost;dbname=oneline_bbs;charset=utf8';
$id = 'root';
$pw = '';

try {
    $pdo = new PDO($dbname, $id, $pw, array(PDO::ATTR_EMULATE_PREPARES => false));
} catch (PDOException $e) {
    exit('データベース接続失敗。' . $e->getMessage());
}


• サーバー接続情報（第一引数）：'mysql:host=ホスト名,dbname=データベース名;charset=文字コード'
	• host：今回は localhost（レンタルサーバーなら指定されたもの。指定がない時は 〜.co.jp など）
	• dbname：今回は oneline_bbs（接続するデータベース名）
	• charset：今回は utf8（データベースで指定した文字コード）

• ユーザーID（第二引数）：今回は 'root'（データベースに接続する時のユーザーID）

• ユーザーパスワード（第三引数）：今回は ''（空文字。上記ユーザーのパスワード）

new PDO() でデータベース接続を実行した際、
接続が確立できなかった時は自動的に例外（PDOException）が出力される。

例外時の処理を安全に実行するため、try-catch 文の形で行う。

今回のプログラムは、データベースに接続できない時は
一切それ以降の処理を実行する必要がないため、例外発生時に exit() で処理を終了させている。
データベース接続処理ではこの形が基本となる。

今回、exit() 時中に出力するメッセージを 
exit('データベース接続失敗。'.$e->getMessage()); としている。

$e->getMessage() には例外の具体的な発生理由が入っており
開発段階ではエラー原因を特定するために必要な情報だが、
実際の運用段階（本番環境）では外部に公開してはいけない情報であるため、
「データベース接続失敗」という文言のみにするのが望ましい。
これは、例外情報の中にデータベースへアクセスを
試みたユーザー情報などが含まれてしまうリスクがあるためである。


PDOのプリペアドステートメント

PDOでは、ユーザーが入力したデータをデータベースに登録する前に、
SQLインジェクション対策を行う。そのため、SQL文の作成時に値を埋め込む場所を、
あらかじめプリペアドステートメント限定の
仮の名前（名前付きプレースホルダ：例 :name や :comment など。名前は自由）で記述しておき、
その後のbind文で「SQLの :〜 には値として〇〇〇をバインドする」と一つずつ指定を行う。

これにより、mysqliの ?（ハテナマーク）を使う方法よりも、
後からコードを見返したときに直感的に理解しやすい形を作成できるようになっている。

※もちろん、mysqliと同様にバインドする値をSQL文中で ? で書くことも可能→プレースホルダ：VALUES (?, ?, ?)

この場合、? に対して左から自動的に 1, 2, 3... と連番が付与される。
バインドする時は「1番目の ? に値をバインドする」というように、
プログラム中には直接書いていない番号を指定して紐付けを行うことになる。


【プリペアドステートメントによるSQL文の開始】
プリペアドステートメント用の変数 = $pdo->prepare(SQL文またはSQL文を代入した変数);
（今回は $stmt を使用。P449にもあるように、Statementの略としてよく使われる変数名）

この命令を実行した後、プリペアドステートメント用の変数（$stmt）を使用して値をバインドしていく。
PDOでは1つの命令で1つの値をバインドする。

【バインドする命令の種類】
• $stmt->bindParam()：バインドする値を「変数」に格納して紐付ける時
（Param = パラメータ変数）。後から変数の値が変わると、実行時の値も変わる。

• $stmt->bindValue()：バインドする値を直接命令内に記入する時、またはその時点の値を固定して紐付ける時
（Value = 直接値の指定）。

->bindValue() や ->bindParam() の引数 () 内で、バインドする値とデータの型を指定する。

• バインドする値が「文字列」または「浮動小数点」の時

	• :〜 の仮の名前（名前付きプレースホルダ）を使用する場合：
$stmt->bindParam(':仮の名前', $変数, PDO::PARAM_STR);
	• ? を使用する場合：
$stmt->bindParam(1, $変数, PDO::PARAM_STR); （※1, 2, 3...は左からの順番）


※型の指定（第3引数）を省略した場合は、自動的に文字列（PDO::PARAM_STR）扱いとなる。
※PDOには「浮動小数点（小数を表す型）」という個別の指定用定数がないため、小数を扱う場合も文字列（PDO::PARAM_STR）として実行する（整数型にしてしまうと、小数点以下が切り捨てられてしまうため）。
• バインドする値が「整数」の時
	• :〜 の仮の名前（名前付きプレースホルダ）を使用する場合：
$stmt->bindParam(':仮の名前', $変数, PDO::PARAM_INT);
	• ? を使用する場合：
$stmt->bindParam(1, $変数, PDO::PARAM_INT);
※整数型（PDO::PARAM_INT）を指定した場合、渡された値が自動的に整数に変換されるため、例えば 13.5 は 13 になり、011 は 11 になる。このように先頭の 0 や小数点以下は削除（型変換）される。

【電話番号の型についての補足】
電話番号の先頭にある 0 は、国内通話を意味している（国番号：日本は +81 に置き換えるシステムもある）。
このため、データベース格納時に先頭の 0 を保持するために文字列型（PARAM_STR）のまま扱うサイトと、あえて数値を削除して管理するサイトが存在する。基本的には先頭の 0 が消えないよう、電話番号は整数型ではなく文字列型で扱うのが一般的である。

SQL文の実行

プリペアドステートメント用の変数 -> execute();
この命令を実行することで、データベースにSQL文（およびバインドされた値）が渡されて実行される。
この時、値をバインドするタイミングが接続方式によって異なる。

• 動的接続（エミュレーションON）：PHP側で値を埋め込んで完全なSQL文を完成させてから、データベースへ送信して実行する。
• 静的接続（エミュレーションOFF）：SQL文の型（テンプレート）とバインドする値を個別にデータベースに渡し、データベースサーバー側で安全に組み立ててから実行する。

【プリペアドステートメントの終了】
データベースの処理（実行）がすべて終わったら、速やかに終了するのが基本である。
PDOのプリペアドステートメントは、使用している変数に null を代入することで終了（オブジェクトの解放）となる。
php
$stmt = null; // プリペアドステートメントの終了
コードは注意してご使用ください。
PDOのプリペアドステートメントは「オブジェクト型」という形式で動作している。オブジェクト型の場合、プリペアドステートメント用の変数（$stmt）には「プリペアドステートメントオブジェクト」の実体（参照）が代入されている。この変数に null を代入すると、オブジェクトがメモリから削除（解放）されるため、プリペアドステートメントも終了する仕組みになっている。
