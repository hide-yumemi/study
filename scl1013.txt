SELECT文を実行し、データベースエリアで
保存されている取得データを、PHPでは1行ずつ切り取る形で取り出しを行う。
これは取得したデータを全件一気に取り出すと、メモリに大きなデータを展開することになってしまうため、
負荷のかからないように1件ずつ行う。
SELECT文実行後
・SELECT文成功
・1件以上のデータ取得
の時に、ループ文で1件ずつ最後までデータを取り出していく。
SELECT文実行後、取得件数を確認
mysqli_num_rows(SELECT文の実行結果を代入した変数)
今回は、$result = mysqli_query(〜);
としているので、() に $result を指定し、
mysqli_num_rows($result);
とする。
今回、取得が1件以上の時は、
1件1件を <li></li>
全体を <ul></ul>
でタグ指定をし、箇条書きリストとして
ブラウザ出力を行っている。
データベースからSELECTした結果を1件ずつ取り出す
取り出したデータを受け取る変数 = mysqli_fetch_assoc(SELECT結果を代入した変数);
この命令は、SELECT結果を1件ずつ、取り出した
変数に連想配列（キーはカラム名）として代入する。
切り取りの形で全データを渡した後は、false を代入する。
終了時に false が代入されるので、while文の条件として使用できる。
if ($result !== false && mysqli_num_rows($result))
の判定について
取得件数0件であった場合、その後の
while($post = mysqli_fetch_assoc($result))
が1周目で $post に false が入り脱出となるため、
mysqli_num_rows($result) は0件でもエラーにならない。
ただし、取得0件だった時でも <ul></ul> は出力となってしまうため、
今回は if文で除外しているが、<ul></ul> が出ることを許容し、
if文を
if ($result != false)
とするサイトも多い。
今回、created_at カラムの出力を
echo htmlspecialchars($post['created_at'], ENT_QUOTES, "UTF-8");
と htmlspecialchars で「"」や「'」をエスケープして出力している。
ただ、今回 created_at カラムに保存している内容は
ユーザーの入力値ではなく、プログラムで作成した文字列（日付）のため、
この処理は行わず、
echo $post['created_at'];
として問題ない。
SELECT文の結果を代入した変数は、
fetch命令で全件取り出した後もデータベースとやり取りはできる
（fetchして false となっても処理は可能）状態となっている。
この状態は解除してからデータベースと切断する。
切断だけして解除しないと、サーバーによってはエラーとなる。
解除命令： mysqli_free_result(SELECT結果を代入した変数);
データベースとの切断
データベースと接続し、データベースの処理がすべて終わったら
すみやかに切断し、データベースの使用権を次のプログラムに渡す。
PHPファイル実行終了で自動切断されるが、それを待たずに切断命令を行い、
少しでも速く明け渡すのが、サイトの混雑時のサイト全体の処理向上に役立つ。
mysqli_close(mysqli_connectを代入した変数);

例外
PHPにおける例外（Exception）とは、プログラムの命令の記述や
使い方、変数の型など、「プログラムの文法としては問題ない」
が、実行しようとするとプログラム以外の問題で失敗となってしまう状態のこと。
例）
• PDOによるデータベース接続の失敗
• 外部のアプリケーションとのデータの送受信の失敗
（クレジットなどの決済処理でのネットワークや相手側サーバーの混雑による失敗）
• 開こうとした外部ファイルが削除されてしまっていた

PHPでは処理が正しく終了できないことを総称して「トラブル」といい、
トラブル ➡ エラー
トラブル ➡ 例外
と、下位に「エラー」と「例外」があるという考え方で開発されているプログラミング言語。
ただし、例外を放置した場合、結果として処理が
正しくなくなってしまい、エラーを出力して終了の形になる。
（画面に 例外：EXCEPTION によるエラーとメッセージが出る）
PDOの接続では、接続失敗時に
PDOException という例外が自動的に出力される。
この PDOException には失敗原因がメッセージとして入っている。
PDO接続の時は、この PDOException が出力された時、
ブラウザに（エラー画面を）出力せずに「例外が出力されたら実行する処理」
を記述する「try-catch」という命令を使用して行う。

try-catch文
try {
    // 実行したい命令
}
catch (throwされた例外 例外を受け取る変数) {
    // 例外発生時の処理
}
try の処理を実行中に例外が出力された場合、それ以降の try の処理は行わず、
catch に移動して catch の処理を行う。
try で例外が発生しなかった時は、catch の処理は実行されない。
PDOのように自動的に例外が出力されない
命令で try-catch 文を使用したい時：
try {
    if (〜):
        throw new Exception('例外メッセージ'); // 条件判定により、手動で例外メッセージをthrow（出力）
    endif;
}
catch (Exception 例外を受け取る変数) {
    // 例外発生時の処理
}
例外メッセージについて
例外メッセージは catch 文内において、
例外を受け取る変数 -> getMessage();
で取得できる。
catch (Exception $e) {
    echo $e -> getMessage();
}
